# הוצאות הבית

אפליקציית שולחן עבודה (Electron) לניהול הוצאות והכנסות חודשיות של הבית - מקומית לחלוטין, בלי ענן ובלי תלות באינטרנט בזמן ריצה. נבנתה עבור שרון ויהונתן יוסילביץ'. מפותחת משני מחשבים (עם Git/GitHub פרטי לסנכרון קוד - ר' "עבודה משני מחשבים" למטה).

## מה זה עושה

- ייבוא נתונים מקבצי **Excel ו-PDF** - דפי עו"ש מהבנק ודפי אשראי מפורטים (ויזה/ישראכרט/מקס), עם אשף ייבוא ב-3 צעדים (בחירת קובץ → מיפוי עמודות → בדיקה ואישור) שאף פעם לא שומר "בעיוורון". יש **זיהוי אוטומטי** של: שורת הכותרות, תפקיד כל עמודה (תאריך/תיאור/סכום/זכות/חובה/תשלומים/מדינה) לפי שם העמודה או לפי הנתונים עצמם, סוג הקובץ (עו"ש/כרטיס מסוים) לפי שם הקובץ או תוכן הקובץ, ו"חורים" בכיסוי דפי הבנק (ימים חסרים בין דפים).
- סיווג כל תנועה לפי **קטגוריה** (רשימת ברירת מחדל רחבה - כספית/בית/מזון/ביטוחים/תקשורת/קופ"ח/AI ועוד, לגמרי ניתנת לעריכה, עם בורר קטגוריה עם חיפוש כי הרשימה ארוכה) ולפי **מי** (שרון/יהונתן/בית, ניתן לעריכה), עם חוקי סיווג אוטומטי לפי מילות מפתח בתיאור שנלמדים עם הזמן - גם ניתן להוסיף חוקים ידנית בהגדרות, לא רק דרך הייבוא.
- **דשבורד חודשי** - קטגוריות כעמודות עם סה"כ לכל עמודה (כבקשת יהונתן - לא כמו טבלת אקסל רגילה), הוצאות קבועות בנפרד, הכנסות בנפרד, כמה נשאר בסוף החודש, ותובנות אוטומטיות (חריגות הוצאה מול ממוצע, תחזית סוף חודש, הוצאות גדולות).
- **מעקב תשלומים** - מסך ייעודי לעסקאות בתשלומים (כרטיס אשראי): תצוגת "פעיל" (כל עסקה פתוחה, כמה תשלומים נשארו, מתי מסתיימת) ותצוגה לפי חודש ספציפי.
- **גרפים** (עוגה/בר/מגמה) ו**השוואת חודשים** (פיבוט: שורות=חודשים, עמודות=קטגוריות) - הכל מסונן לפי חודש/אדם.
- **נעילת PIN אופציונלית** - קוד 4+ ספרות עם קוד גיבוי אופציונלי, מוגדר בהגדרות. ר' "נעילת PIN" למטה - **חשוב**: זו הגדרה מקומית, לא מסונכרנת בין מחשבים.
- שמירת **היסטוריה של כל החודשים**, גיבוי אוטומטי (10 גיבויים אחרונים) + ייצוא/שחזור גיבוי ידני.

## נעילת PIN - מה חשוב לדעת

PIN (ו-hash של קוד גיבוי, אם הוגדר) נשמרים בתוך `settings` בקובץ **data.json המקומי** (`%APPDATA%\הוצאות הבית\data.json`) - **לא** בקוד, ולכן **לא** מסונכרן דרך Git בין המחשבים. המשמעות בפועל:

- **PIN שהוגדר במחשב אחד לא "יעבור" למחשב השני אוטומטית**, גם אחרי `git pull` - כי ה-pull מעדכן רק קוד, לא נתונים. כל התקנה שומרת PIN נפרד משלה (או בלי PIN בכלל, אם עדיין לא הוגדר שם).
- אם רוצים את **אותו** PIN בשני המחשבים - צריך להגדיר אותו ידנית בכל מחשב בנפרד (הגדרות → הגדרת PIN), **או** לייצא גיבוי מהמחשב שבו כבר הוגדר PIN (ההגדרות כולל ה-PIN נכללות בגיבוי) ולשחזר אותו במחשב השני.
- מחשב בלי `pinHash` בקובץ הנתונים שלו פשוט **לא מציג מסך נעילה בכלל** - נכנסים ישר לאפליקציה.
- ה-PIN עצמו לא נשמר כטקסט גלוי - נשמר רק ה-hash (SHA-256 + salt קבוע), ב-`src/pages/LockScreen.jsx`.

## סטאק טכנולוגי

Electron + React (JS, לא TS) + Vite, אריזה ל-installer של Windows (NSIS) דרך `electron-builder`. אחסון נתונים כקובץ JSON תחת `app.getPath('userData')` (לא SQLite - בכוונה, כדי להימנע מ-native modules שמסבכים אריזה; בהיקף נתונים של הוצאות בית זה לגמרי מספיק).

```
electron/
  main.js            # תהליך ראשי: חלון, IPC handlers, גיבויים
  preload.js          # contextBridge - ה-API הבטוח שנחשף ל-renderer כ-window.api
  dataStore.js         # קריאה/כתיבה אטומית של data.json + גיבויים מתגלגלים + ברירות מחדל (קטגוריות/חוקים)
  lib/importExcel.js   # פענוח Excel (xlsx) - raw:true חשוב! (ר' "מלכודות" למטה) + guessHeaderRowIndex משותף
  lib/importPdf.js     # פענוח PDF (pdfjs-dist) - חילוץ טקסט+מיקום, קיבוץ לשורות/עמודות גלובלי, סינון boilerplate, תיקוני bidi
src/
  DataContext.jsx      # React context - טוען/שומר נתונים דרך window.api
  App.jsx              # sidebar + ניתוב פשוט מבוסס state (בלי react-router) + מסך נעילה
  pages/
    Dashboard.jsx        # תובנות (insights.js) + פיבוט קטגוריות
    ChartsPage.jsx, History.jsx, Transactions.jsx, Settings.jsx
    Installments.jsx     # מעקב עסקאות בתשלומים
    LockScreen.jsx        # מסך PIN + hashPin()
    Import.jsx            # אשף ייבוא - הכי גדול, כולל auto-detection (ר' למטה)
  components/
    FilterBar.jsx, CategorySelect.jsx   # בורר קטגוריה עם חיפוש (הרשימה ארוכה)
  lib/
    aggregate.js        # פונקציות טהורות לחישובי סכומים/פיבוט - עם בדיקות
    categorize.js         # התאמת חוקים + זיהוי "חיוב לכרטיס" מרוכז / יתרת פתיחה
    insights.js            # detectAnomalies, forecastMonthEnd, topExpenses, categoryAverages
    parseDate.js             # נירמול תאריכים (ISO/DD-MM-YYYY/סריאל אקסל) וסכומים
    palette.js                # צבעי הקטגוריות בגרפים (recharts)
```

### זיהוי אוטומטי בייבוא (`Import.jsx`)

- `detectFileType` - מזהה "עו״ש" מול כרטיס ספציפי לפי **שם הקובץ** (מכיל 4 ספרות של כרטיס ידוע).
- `autoDetectColumnRoles` - ממפה עמודות אוטומטית: קודם לפי **שם הכותרת** (מילות מפתח בעברית/אנגלית), ואם משהו חסר - לפי **דפוס הנתונים עצמם** (עמודה שרוב הערכים בה הם תאריך תקין → תאריך, וכו').
- `autoDetectCardFromFile` - סורק את **תוכן** הקובץ (לא רק שם הקובץ) לזיהוי מספר כרטיס, למקרה ששם הקובץ לא מספיק.
- `detectBillingCycle` + `computeBankGaps` - מזהים את מחזור החיוב (10 לחודש עד 9 לחודש הבא) ומתריעים אם חסרים ימים בכיסוי דפי הבנק שיובאו (למשל דף שלא יובא בין שני דפים אחרים).
- `KNOWN_CARDS` / `REPLACED_CARDS` / `OCCASIONAL_CARDS` - רשימות קשיחות בראש `Import.jsx` שכדאי לעדכן אם מספרי הכרטיסים משתנים (למשל כרטיס שהוחלף).

## פקודות

```bash
npm install       # פעם ראשונה (וכל פעם שמשנים dependencies)
npm run dev        # הרצה בפיתוח (Vite + Electron ביחד)
npm test           # vitest - הבדיקות ב-src/lib/*.test.js וב-electron/lib/*.test.js
npm run build       # build בלבד (dist/ + dist-electron/)
npm run dist         # build + electron-builder -> release/*.exe (דורש Developer Mode - ר' מלכודות)
```

## עבודה משני מחשבים

הקוד מסונכרן דרך מאגר Git **פרטי**: `https://github.com/SharonYosilevich/Expenses`. **הנתונים (data.json, גיבויים, PIN) לא מסונכרנים** - הם מקומיים לכל מחשב בנפרד (ר' "נעילת PIN" למעלה לגבי הנפקות מכך).

לפני שמתחילים לעבוד במחשב כלשהו: `git pull`. אחרי שמסיימים שינוי: `git add -A && git commit -m "..." && git push`. אם `npm install` נדרש (package.json/package-lock.json השתנו), להריץ לפני `npm run dev`.

## מלכודות שכבר נתקלנו בהן (חשוב לזכור!)

1. **Excel dates - חובה `raw: true`** ב-`sheet_to_json` (ב-`electron/lib/importExcel.js`). עם `raw:false` SheetJS מחזיר טקסט מפורמט לפי לוקאל ברירת מחדל (M/D/YY, אמריקאי) גם אם הקובץ המקורי בפורמט ישראלי - זה גרם לכל התאריכים להיכשל בפענוח וב-0 תנועות מיובאות. עם `raw:true` + `cellDates:true` מקבלים אובייקט `Date` אמיתי וממירים בעצמנו (ר' `cellToString`). גם שימי לב ל-`getFullYear/getMonth/getDate` (לוקאלי) ולא `toISOString()` (UTC) - זה יכול להזיז תאריך יום אחורה.

2. **שורות "חיוב לכרטיס ויזה/ישראכרט/מקס" בדף עו"ש הן סכום מרוכז**, לא הוצאה מפורטת - הפירוט האמיתי (מזון/דלק/כיף) צריך לבוא מדף האשראי המפורט. לכן `isLikelyCardAggregate()` מסמן אותן באזהרה ומשאיר אותן **לא מסומנות לייבוא כברירת מחדל** (`Import.jsx`, `buildDraftRows`) - כדי למנוע כפילות אם מייבאים גם את דף האשראי המפורט.

3. **תנועות בלי התאמת חוק לא אמורות ליפול על הקטגוריה הראשונה ברשימה** - יש פולבאק מפורש ל"אחר"/"בית" (ניטרלי, מסמן "צריך בדיקה") במקום שהכל ייראה כאילו זה "בית" כברירת מחדל.

4. **`ELECTRON_RUN_AS_NODE=1`** מוגדר בסביבת ה-shell של סוכן הפיתוח (Claude Code) - זה גורם ל-`electron.exe` לרוץ כ-Node רגיל במקום Electron אמיתי (require('electron') מחזיר undefined). צריך להסיר את המשתנה הזה (`delete env.ELECTRON_RUN_AS_NODE`) לפני שמריצים את ה-binary בבדיקות.

5. **contextBridge לא ניתן ל"stub"/override מה-renderer** - כדי לבדוק את זרימת הייבוא בלי לפתוח דיאלוג קבצים אמיתי, צריך לתפוס את זה בתהליך הראשי (`app.evaluate(({ipcMain}) => ipcMain.handle('import:pickFile', ...))`), לא ע"י שינוי `window.api` מה-renderer.

6. **בניית installer דורשת Windows Developer Mode פעיל** (Settings → מערכת → למפתחים) - אחרת `electron-builder` נכשל בחילוץ `winCodeSign` (symlinks של macOS בתוך הארכיון) עם שגיאת הרשאות. אפשר לכבות את Developer Mode אחרי הבנייה - לא נדרש להרצת האפליקציה המותקנת.

7. **`pdfjs-dist` חייב להיות ב-`dependencies`** (לא `devDependencies`) כי הוא נטען ב-runtime ב-main process (`electron/lib/importPdf.js`) ו-`electron-builder` אורז רק production dependencies.

8. **`pdfjs-dist` v4 הפסיק לספק build של CommonJS** - `require('pdfjs-dist/legacy/build/pdf.js')` לא קיים יותר, יש רק `.mjs`. חייבים `await import('pdfjs-dist/legacy/build/pdf.mjs')` (דינמי) מתוך `importPdf.js` שהוא עצמו CommonJS.

9. **גבולות עמודות ב-PDF חייבים להיות מחושבים גלובלית (כל העמודים ביחד), לא לכל עמוד בנפרד** - אחרת אותו קובץ PDF מקבל "פירוש" שונה לעמוד 2 מאשר לעמוד 1 (`clusterColumns` ב-`importPdf.js` מקבל את כל השורות מכל העמודים).

10. **בבדיקת "האם יש כאן תאריך" - חובה להתאים פורמט DD/MM/YYYY בפועל**, לא רק "התא לא ריק" - אחרת כותרת עמודה כמו "תאריך עסקה" (הטקסט של שם העמודה) עוברת את הבדיקה בטעות ונחשבת כאילו יש בה תאריך אמיתי.

11. **שם עסק ב-PDF יכול "לגלוש" לשורה נפרדת גם לפני שורת התאריך/סכום וגם אחריה** (`mergeOrphanDescriptionLines` ב-`importPdf.js`), ותוכן התיאור לא תמיד נופל באותו אינדקס עמודה בין שורות שונות (`collapsePreDateColumns` מאחד את כל מה שלפני עמודת התאריך לעמודה אחת, כדי לא להיות תלוי במיקום מדויק). מקרה גבולי שנשאר: כשתיאורים "גולשים" של שתי עסקאות שונות נפגשים ברצף בלי שורת תאריך ביניהן, הם עלולים להתערבב זה בזה (התאריך/סכום נשארים נכונים, רק שם העסק עלול להכיל מילה מיותרת).

## מה עוד לא נבדק/נבנה

- ייבוא PDF נבדק היטב על דף עו"ש בנק ודף אשראי מפורט אחד (ויזה) - שני הפורמטים נכנסים נקי ברוב המקרים. **המלצה: לדפי אשראי מפורטים, אם יש אפשרות, עדיף לייצא ולייבא את קובץ ה-Excel** מאתר הבנק - הוא נכנס נקי לגמרי, בלי אף אחת מהמורכבויות של פענוח PDF.
- אין אייקון מותאם אישית ל-installer (משתמש באייקון ברירת המחדל של Electron) - `build/icon.ico` אם ירצו להוסיף בעתיד (ולעדכן `package.json` -> `build.win.icon`).
- אין code signing (חתימה דיגיטלית) ל-installer - Windows SmartScreen עלול להציג אזהרה "Unknown publisher" בהתקנה הראשונה; זה תקין וניתן ללחוץ "עוד מידע" -> "הפעל בכל זאת".
